# ران‌بوک عملیات هامزیار X (🌊 W3/MISS-05)

## ۱) سرویس‌ها و سلامت

تک‌کانتینر با `supervisord`: سرویس `api` (uvicorn روی `$PORT`) + سرویس `bot` (polling).

| چک | روش |
|---|---|
| API زنده است؟ | `GET /api/health` (هلث‌چک Railway همین است) |
| سلامت عمیق (DB + ربات) | `GET /api/health/deep` |
| ربات پیام می‌گیرد؟ | لاگ `supervisor:bot` + فایل ضربان (`BOT_HEARTBEAT_FILE` یا `/tmp`) |
| فرانت‌ها سرو می‌شوند؟ | `/app/` مینی‌اپ، `/admin/` وب‌ادمین |
| مستندات API بسته است؟ | `/docs` باید 404 بدهد (در prod)؛ فقط با `API_DOCS_ENABLED=1` باز است |

## ۲) حالت webhook (⚠️ پشتیبانی نمی‌شود)

مسیر سالم و تست‌شده **polling** است. حالت webhook (`BOT_WEBHOOK_MODE=1` + `WEBHOOK_URL`) روی Railway تک‌پورت کار نمی‌کند (پورت با uvicorn تداخل می‌کند) و فقط برای سازگاری/دیباگ در کد مانده؛ با فعال‌بودن آن، ربات در استارتاپ هشدار می‌دهد.

- اگر ربات پیام نمی‌گیرد: اول چک کن `BOT_WEBHOOK_MODE` و `WEBHOOK_MODE` **خالی** باشند.
- حذف کامل شاخه‌ی webhook عمداً انجام نشده (تغییر پرریسک)؛ اگر روزی خواستی حذفش کنی، `bot.py` (تابع main) + تست `test_bot_startup_resilience.py` را هم‌زمان به‌روز کن.

## ۳) درگاه زرین‌پال

| حالت | شرط | رفتار |
|---|---|---|
| نمایشی (mock) | `ZARINPAL_MERCHANT_ID` خالی | لینک `TEST-`، verify همیشه موفق، پول واقعی صفر |
| سندباکس | مرچنت test + `ZARINPAL_SANDBOX=1` | درگاه آزمایشی زرین‌پال |
| واقعی | مرچنت ۳۶ نویسه‌ای واقعی | پول واقعی |

تنظیمات دیتابیسی (`zarinpal_merchant_id` و...) از پنل ادمین بدون ری‌استارت اعمال می‌شوند (کش ۳۰ ثانیه‌ای) و بر env اولویت دارند. دکمه‌های «پرداخت آنلاین» فقط وقتی دیده می‌شوند که `zarinpal_enabled` روشن باشد.

- کال‌بک پیش‌فرض: `WEBAPP_URL + /payment/verify`. کال‌بک دلخواه کلاینت فقط اگر https و هم‌مبدأ باشد پذیرفته می‌شود.
- پرداختِ رها‌شده بعد از ۱ ساعت خودکار `cancelled` می‌شود و hold درگاه (در صورت وجود) با reverse آزاد می‌شود؛ نتیجه در فیلدهای `zarinpal_reversed/*` روی سند ثبت است.

## ۴) بازگشت وجه و بازوی درگاهی

بازگشت وجه از وب‌ادمین = `approved→refunded` اتمیک + اعتبار **کیف پول داخلی** (نه درگاه). اگر رسید درگاهیِ verifyشده باشد (`zarinpal_ref_id` دارد)، فیلد `gateway_reversal=manual_required` می‌خورد و به اپراتور هشدار داده می‌شود: **برگشت درگاهی را دستی در پنل زرین‌پال ثبت کن** (reversal خودکار فقط برای پرداخت‌های verifyنشده ممکن است).

## ۵) سقف روزانه‌ی کیف پول (fail-closed)

تنظیم دستی ادمین بالای `WALLET_DAILY_LIMIT` (پیش‌فرض ۵٬۰۰۰٬۰۰۰ تومان) با **429** رد می‌شود. اگر سامانه‌ی سقف به‌خاطر خطای DB در دسترس نباشد، تراکنش **متوقف** می‌شود (503) و لاگ `CRITICAL` می‌خورد — این رفتار عمدی است (fail-closed) تا سقف مالی دور زده نشود:

1. سلامت Mongo را چک کن (`/api/health/deep`).
2. لاگ `database` را برای خطای aggregate ببین.
3. بعد از رفع، ادمین دوباره تلاش کند — هیچ اثر نصفه‌ای نوشته نشده.

## ۶) ریت‌لیمیت‌ها

لایه‌ی سراسری: هر IP روی `/api/*` حداکثر **۱۲۰ درخواست/دقیقه** (پاسخ 429 با `Retry-After`). سقف‌های اختصاصی (کاربر/دقیقه، مگر ثبت‌نام):

ثبت‌نام ۵/۱۰دقیقه؛ تیکت ۱۰؛ پاسخ تیکت ۳۰؛ گزارش تخلف ۱۰؛ پاسخ سؤال ۱۰۰؛ تولید AI تمرینی ۱۰؛ ساخت job درون‌ریزی ۳۰؛ دانلود مرجع ۶۰؛ خرید/تخفیف/verify طبق کد.

با `RATE_LIMIT_ENABLED=0` همه خاموش می‌شوند (فقط تست/دیباگ؛ در prod روشن نگه دار).

## ۷) مغایرت‌گیری مالی

`/admin` → اشتراک‌ها → **مغایرت‌گیری**. هر مورد `severity` و اقدام دارد. موارد مهم W3:

- `approved_discount_overrun` — کد تخفیف بعد از پول قطعی ظرفیت نداشت؛ پرداخت approve شده و تخفیف خارج از ظرفیت داده شده. اقدام: بازبینی مدیریتی (تصمیم جبرانی با محصول).
- `approved_topup_not_credited` — شارژ تأییدشده بدون اعتبار؛ اقدام «اعمال اعتبار شارژ» (idempotent).
- `refunded_but_active_sub` — بازگشت وجه بدون revoke؛ تصمیم آگاهانه بگیر.

## ۸) بکاپ و بازیابی

- بکاپ خودکار روزانه (تلگرام، سقف ۵۰MB) با ساعت قابل‌تنظیم از پنل (`auto_backup_*`)؛ نگه‌داشت با `BACKUP_AUTO_KEEP` (پیش‌فرض ۱۴ روز).
- ⚠️ با رشد دیتا بالای ~۵۰MB بکاپ تلگرامی می‌شکند — قبل از آن offsite (S3/...) لازم است (در نقشه‌ی موج‌های بعد).
- 🌊 W5: گیت حجم — بالای ۴۸MB ارسال انجام نمی‌شود و جاب fail می‌خورد (هشدار موجود)؛ بالای ۴۰MB لاگ warning. فایل `.json.enc` یعنی رمزنگاری‌شده.
- 🌊 W5: اگر `FERNET_KEY` ست باشد، بکاپ خودکار رمزنگاری (Fernet) می‌شود و بازیابی با همان کلید انجام می‌شود؛ **کلید را جدا از بکاپ نگه دار** (گم‌شدن کلید = بکاپ غیرقابل‌بازیابی).
- 🌊 W5: بکاپ کامل اثر `sha256_sections` دارد؛ ناسازگاری در restore = توقف بازیابی (فایل خراب/دست‌کاری‌شده).
- 🌊 BACKUP-JALALI: خروجی همه‌ی بکاپ‌ها **gzip** است (`.json.gz`، و اگر رمز بود `.json.gz.enc`)؛ بازیابی از پنل ربات هر ۴ شکل (`.json` / `.json.gz` / با و بدون `.enc`) را می‌خواند. نسخه‌ی بکاپ `3.1`؛ datetimeها تگ‌دار و قابل‌بازیابی دقیق‌اند.
- بازیابی: فایل را از مسیر «📥 بازیابی از فایل» در پنل بکاپ ربات آپلود کن؛ بعد از restore حتماً `ensure_indexes` اجرا شده باشد (استارتاپ خودش اجرا می‌کند).

## ۹) حادثه‌های رایج

| علامت | اقدام |
|---|---|
| کاربر پول داده ولی اشتراک فعال نشده | در `sub_payments` با `zarinpal_authority` پیدا کن: اگر `zarinpal_pending` است، کاربر دکمه‌ی «بررسی» را نزده — خودش/ادمین verify کند؛ اگر `cancelled (timeout)` است، hold با reverse آزاد شده و باید دوباره بخرد |
| `discount_overrun` روی رسید | طبیعیِ مسیر مسابقه؛ طبق §۷ بازبینی کن |

| موج 429 روی یک IP | حمله/اسکریپت یا باگ فرانت (حلقه)؛ لاگ API و `X-Request-ID` را دنبال کن |
| ربات silent است | §۱ و §۲؛ بعد صف `bot_notifications` (sent=Falseِ انباشته = sender خوابیده) |
| دیسک در حال پر شدن | retention روزانه‌ی `audit_logs` ساعت ۰۳:۳۰ اجرا می‌شود (`audit_retention_days`، پیش‌فرض ۳۶۵)؛ آخرین اجرا در setting ‏`audit_retention_last_run` |

## ۱۱) trial، سهمیه پلنی و RBAC تفویض‌شده (🌊 W6)

- trial: تنظیمات `trial_enabled` (پیش‌فرض روشن) و `trial_days` (۱..۳۰، پیش‌فرض ۷) از مرکز تنظیمات (دسته‌ی اشتراک)؛ هر کاربر یک‌بار؛ معادل ارزان‌ترین پلن فعال.
- سهمیه هوشیار: هر پلن `ai_daily_limit` دارد (۰ = ارث از سقف سراسری `daily_limit`)؛ اشتراک‌های دستی/قدیمی بدون plan_id از تطبیق نام یا سراسری استفاده می‌کنند.
- هر ۴ روتر مدیریتی (`/api/admin/*`، ai-mgmt، subscription-mgmt + بخش‌های باقی‌مانده‌ی web-admin) از owner-only به `require_perm` مهاجرت کردند؛ مالک بدون تغییر (bypass) و نقش‌ها فقط با مجوز صریح.
- جستجوی سراسری: timeout کلی ۸ ثانیه (۵۰۳ + «دوباره تلاش کن») و maxTimeMS پنج‌ثانیه‌ای هر کوئری؛ ۵۰۳ مکرر = ایندکس/بار را بررسی کن.
- تصمیم «تمدید خودکار واقعی نداریم» در `docs/auto-renew-decision.md` مستند است.
