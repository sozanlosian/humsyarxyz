# چرا «تمدید خودکار» واقعی نداریم؟ (MISS-03 — 🌊 W6)

> وضعیت: تصمیم محصولِ آگاهانه، نه بدهی فنی.

## ۱) تمدید خودکار واقعی یعنی چه؟

شارژ دوره‌ای کارت کاربر **بدون اقدام او** (recurring billing). این نیاز دارد به:

1. ذخیره‌ی توکن/کارت (card-on-file) نزد درگاه یا PSP؛
2. قرارداد recurring با شاپرک/درگاه؛
3. رضایت صریح و لغو آسان (الزام حقوقی).

## ۲) چرا الان نشدنی است؟

- زرین‌پال (درگاه فعلی) recurring/card-on-file عمومی ندارد؛ هر پرداخت
  نیازمند بازگشت کاربر به درگاه است.
- پیاده‌سازی «شبه‌خودکار» (مثلاً برداشت از کیف پول بدون اجازه) هم از نظر
  اعتماد کاربر و هم حقوقی قابل‌دفاع نیست.

## ۳) چه چیزی به‌جایش داریم؟ (کافی برای امروز)

| مکانیزم | کجا |
|---|---|
| یادآوری ۳روزه و ۱روزه + پیام انقضا، هرکدام با دکمه‌ی «تمدید کن» | `bot.py::subscription_expiry_job` |
| اینباکس قطعیِ دیده‌شدن (انقضا/یادآوری) | `inbox_add` در همان جاب |
| تمدید با حفظ روزهای باقی‌مانده (`extend=True`) | `db/finance.py::sub_activate` |
| دوره‌ی آزمایشی برای جذب | `trial_claim` (همین موج) |

## ۴) اگر روزی درگاه recurring آمد

1. رضایت صریح + لغو یک‌کلیکه (قانون)؛
2. `plan.recurring_price` جدا از قیمت تکی؛
3. جاب شارژ + idempotency + اطلاع‌رسانی قبل/بعد؛
4. تست کرش وسط شارژ (مثل قراردادهای `docs/db-no-transactions.md`).
