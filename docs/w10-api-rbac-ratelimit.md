# 🌊 W10 — سقف‌های نرخ + نگاشت RBAC ربات

## ریت‌لیمیت (روی global net قدیمی ۱۲۰/دقیقه/IP)

| نقطه | scope | سقف |
|---|---|---|
| جست‌وجوی سراسری | `search_q` | ۳۰/دقیقه به‌ازای کاربر |
| لیدربورد | `leaderboard` | ۶۰/دقیقه به‌ازای کاربر |
| ارسال broadcast | `broadcast_send` | ۵/دقیقه به‌ازای ادمین |
| خروجی اکسل/CSV (۳ تا) | `export_*` | ۱۰/دقیقه به‌ازای ادمین |
| پیش‌نمایش/اکشن گروهی (۲ تا) | `bulk_preview`/`tickets_bulk` | ۱۰/دقیقه به‌ازای ادمین |

پاسخ محدودیت: `۴۲۹ rate_limited` + هدر `Retry-After`.
غیرفعال‌سازی سراسری (تست): `RATE_LIMIT_ENABLED=0`.

## RBAC ربات (جایگزین `uid == ADMIN_ID`)

| مسیر | پرمیشن |
|---|---|
| مدیریت/فیلتر/جست‌وجو/مشاهده/اولویت/وضعیت/بستن/بازگشایی تیکت | `tickets.manage` |
| پاسخ/پاسخ آماده/پیش‌نویس هوشیار تیکت | `tickets.reply` |
| جست‌وجو/ویرایش کاربر (متن) | `users.view` / `users.manage` |
| افزودن درس/مبحث (متن) | `content.manage` |
| افزودن ورودی (متن) | `settings.manage` |
| ویرایش برنامه (متن) | `schedules.manage` |
| broadcast و حالت‌های اشتراک (متن) | `broadcast.send` / `subscription.manage` |
| پنل مدیریت اشتراک (کال‌بک) | `subscription.manage` |

- `ADMIN_ID` در `has_permission` همیشه True ⇒ بوت‌استرپ و رفتار مالک بی‌تغییر.
- خطای DB در گیت ⇒ fallback به رفتار قدیمی (فقط مالک).
- عمداً دست‌نخورده: بای‌پس approved (کادر عملاً approvedاند)، گیت «پنل ادمین»
  (از قبل role-aware بود)، گیرنده‌ی نوتیف‌های تیکت (روتینگ، نه دسترسی).
